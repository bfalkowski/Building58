Glossary

The words the room uses. Each means one thing, and the manual uses no other word for it.

Activity
The feed on the page of who started and finished what, prompts, turns and permission waits. A huddle report takes its place until you close it.
Add worker
The panel's button that starts a plain session in a folder, in a checkout of its own unless you tick Use this folder. See Add worker.
Base
The branch a ticket starts from and its PR goes against, shown on its card. See Which branch a ticket starts from.
Board
The panel of tickets, in the columns Triage, Ready, Building, In review, Waiting on you and Done, with Rejected folded under it. Not the wall board. See The life of a ticket.
Brief
The first prompt the relay types into a session the room starts: the ticket for a Dev, the review for a reviewer, the idea for the PM, and the Lead's standing instructions. What a role "is told" is in its brief, which is words, not a lock.
Bring back
Starts a stopped task's worker again, in the same conversation and the same checkout. For sessions that are not a task's worker, see Resume.
Channel
A name that joins callers to one world page on the relay. The room uses office by default. Each channel is a separate room with its own sessions and tickets.
Chat channel
One list of posts on the chat board: #office, one per started ticket, or a fun one you make. Always "chat channel", so it is not mixed up with a channel. See The chat board.
Checkout
A separate working copy of a repo, which git calls a worktree, in the repo's .worktrees folder. Each task, Add worker session and PR reviewer gets one. See Copies of the repo.
Clean up
Removes a checkout once nobody is in it. The branch stays.
Desk
One of the nine places a session can have. A session holds its desk until it ends. See How assignment works.
Dev
The worker on a task: it builds the ticket in its checkout and opens one PR.
Floor
On the page, the list of everyone in the room and what they are doing. For the Lead, what ticket.js floor prints. See What the Lead sees.
Hook
A Claude Code event, sent to the relay by relay/office-hook.js. Hooks are how the room knows what a session is doing. See Hooks and typing.
Huddle
One short report on everyone, from what the relay already knows. Asking idle sessions and telling the Lead are separate, and spend tokens. See Huddles.
Job
A command a session started that still runs after its turn ended, such as npm test in the background. A session with one is busy, not idle. See How the relay sees a job.
Lead
The one session you choose with Make this the Lead. It keeps work moving and does what you let it. Not the same as the person sitting at the Lead's desk. See The Lead.
Manager
Two things, kept apart by context. You are the manager of the squad. The manager on the page is the person in a suit who walks through every so often, and changes nothing but where people stand.
Merged elsewhere
Marks a Triage or Ready ticket Done with the PR that delivered it outside the room. See Work that merged outside the room.
COO
The session Ask the COO starts, which reports on how the room runs and proposes at most 3 changes. See The COO.
Security officer
The session Ask security starts, which reports what access the room's sessions run with, by name only, and proposes at most 3 changes. See The security officer.
PM
The session Ask the PM starts, which splits your idea into tickets in Triage.
Quiet
A session in a turn with no hook for the stall time (30 minutes), whose screen still moves. It may be thinking, so it is not stuck. See Is a session alive. A huddle also flags a session as quiet when no hook was heard from it for 15 minutes, whatever its screen does.
Relay
The local server that runs every session, hears every hook, keeps the state and serves the page. See What the relay is.
Resume
The panel's box for a session id: Add worker then starts that old conversation in the folder you give it.
Reviewer
A session that reads one PR and posts its findings. One started for a PR leaves by itself once it has posted. See Reviews.
Rung
A step on the trust ladder in docs/constitution.md article 5: a move handed from the person to the room, off until a person turns it on. See The trust ladder.
Safe to stop
The Floor's verdict that nobody is waiting on a session. See the verdict. On a desk, Safe to stop also needs it to be one of the two kinds the Lead stops, and comes with a Stop button. See What each desk says.
Saved message
Text the relay keeps until a session can safely take it, then types. See Saved messages.
Session
One running Claude Code conversation. Each one the room sees gets a person on the page.
Session host
The small process that runs every session's claude, so a relay restart leaves them running. The supervisor starts it. See the session host.
Stuck
A session in a turn with no hook and no output for the stall time (30 minutes), or a session the relay typed a message into that did not begin a turn, even after the relay tried once more. The Floor says which, and for how long. See Is a session alive and A session that does not start.
Supervisor
The small process that runs the relay and the session host, and starts the relay again after Update. See the supervisor.
Task
A ticket being worked: a checkout, a branch and a worker, with its own state in the Tasks panel. A task can have no ticket, from New task.
Tasks panel
The panel that lists tasks, where you move them between Building, In review, Changes requested, Waiting on you and Done.
Ticket
Work that exists before anyone starts on it, on the Board. Starting it makes a task.
Tired
How much of its context window the Lead has used since its last /clear or refresh: fresh, getting tired, or needs a refresh. See How tired the Lead is.
Token
What a session the room started sends to the relay instead of the key. It reaches only the routes its role allows. See What a session's token reaches.
Update
The room bar's button that fetches merged code for the relay's folder, and pulls it in just before it restarts the relay when relay code changed. See Update, after a merge.
Wall board
The board on the brick wall in the scene. It lists tasks, not tickets, and a "needs you" note for anyone with a hand up.
WIP limit
How many tasks can be building at once: 3, unless you change it in Settings or set RELAY_WIP_LIMIT. See the limit.
Worker
Any session at a desk that is not the Lead. A task's worker is its Dev.
When the room gets a new word, add it here in the same pull request.
